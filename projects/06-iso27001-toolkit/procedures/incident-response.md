# ISO 27001:2022 — Incident Response Procedure

| Field | Value |
|---|---|
| **Owner** | Security Lead / CTO |
| **Review Cycle** | Annually |
| **Standard** | ISO/IEC 27035 (Information Security Incident Management) |
| **Context** | LendStack SaaS Platform |

## 1. Purpose and Scope
This procedure defines how LendStack detects, responds to, and recovers from information security incidents. An "incident" is any event that compromises the Confidentiality, Integrity, or Availability (CIA) of LendStack data or systems. This includes everything from a phishing email to a database breach.

## 2. The Incident Response Team (IRT)

| Role | Assigned To | Responsibility |
|---|---|---|
| **Incident Commander (IC)** | Security Lead | Owns the incident. Makes final decisions. Communicates with the CTO. |
| **Technical Lead (TL)** | Head of Engineering | Directs the engineering response (patching, log analysis, containment). |
| **Communications Lead (CL)** | CTO / Marketing | Handles internal and external comms (customers, regulators, press). |
| **Legal / Privacy Lead** | Legal Counsel | Determines GDPR/breach notification requirements (72-hour rule). |

## 3. Severity Classification

| Level | Description | Examples | Response Time |
|---|---|---|---|
| **P1 (Critical)** | Active breach impacting multiple tenants or core financial operations. | SQL injection leading to data theft, Ransomware, Database deletion. | Immediate (24/7) |
| **P2 (High)** | Breach impacting a single tenant or privileged account. | Stolen admin JWT, Rogue insider (self-approved transfer), SSRF to cloud metadata. | < 2 Hours |
| **P3 (Medium)** | Failed attack, minor policy violation, or isolated malware. | Failed brute-force attempt, Phishing email reported by user. | < 24 Hours |
| **P4 (Low)** | Minor security event, false positive, or non-compliance finding. | Lost USB drive (no PII), Dependabot alert for low CVE. | Next Business Day |

## 4. The 5 Phases of Response

### Phase 1: Preparation
- **On-call Rotation:** The Security Lead and Head of Engineering are on a 24/7 on-call rotation for P1 events.
- **Tooling:** Access to AWS Console, Datadog, and LendStack DB requires hardware MFA (YubiKey).
- **Playbooks:** Pre-approved playbooks exist for common attacks (see `03-siem-detection/playbooks/`).

### Phase 2: Detection & Analysis
- **Triage:** The SIEM (LendStack uses Fluent Bit + Splunk/Sentinel) triggers alerts based on detection rules (e.g., `LDS-AUTH-001` for Brute Force).
- **Investigation:** The Technical Lead confirms if the alert is a False Positive or a True Positive. 
- **Scoping:** Determine the blast radius. Which tenants are affected? What data was accessed?

### Phase 3: Containment
*Goal: Stop the bleeding.*
- **Short-term:** Block the attacker's IP at the WAF, disable the compromised user account, or revoke active JWTs (requires Token Versioning per V-04 fix).
- **Long-term:** Patch the vulnerability, rotate all credentials, or apply the DB constraint (e.g., Maker-Checker). 

### Phase 4: Eradication & Recovery
- **Eradication:** Ensure the root cause is completely removed. (e.g., If the attacker used an SSRF to access AWS metadata, block `169.254.169.254` and rotate IAM roles).
- **Recovery:** Restore systems from clean backups. Test the fix. Monitor closely for re-entry (e.g., watch the IP blocklist for scan attempts).

### Phase 5: Post-Incident Activity
- **Post-Mortem:** A blameless post-mortem meeting is held within 5 days of a P1/P2 incident.
- **Root Cause Analysis (RCA):** Document what happened, why it happened, and what changes need to be made.
- **Action Items:** Update the Risk Register (#6) and create Jira tickets to fix the underlying issue.
- **Regulatory Reporting:** If PII was breached, the Legal Lead must notify the ICO (or relevant authority) within 72 hours (GDPR Article 33). Customers must be notified without undue delay.

## 5. Integration with Technical Controls
This procedure relies heavily on the technical systems built in other projects:
- **Detection:** Alerts are generated by rules like `LDS-AUTH-001` in [#3 (SIEM)](../../03-siem-detection/).
- **Containment:** Requires the ability to revoke tokens, which is missing (V-04) and fixed via token versioning.
- **Investigation:** Uses the Audit Logs and Request IDs designed in [#1 (Architecture)](../../01-saas-architecture/) and the enrichment scripts in [#3](../../03-siem-detection/).
